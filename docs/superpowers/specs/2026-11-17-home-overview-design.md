# 主页（今日概览）设计 — A

> 历史设计记录。R4 的实际行为见根目录 README-D-Insights.md 和 页面功能设计与交接.md。当前 Home 按反馈完成日期统计，估计评价依赖 D 的冻结快照和样本资格；下文“已完成或已超时”和可编辑预估的旧方案已被替代。

## 目的
主页是打开 App 后的第一个页面。早上先问候并回顾昨天（先鼓励、后提醒、给评分），其余时间直接看今天的安排。19 号 demo 用它讲出 Tempo 的卖点：“你又低估了时间”。

## 已确定（用户决定）
- 主页 = 今日概览，作为启动页。
- 07:00–09:00 打开：先显示问候 + 昨日回顾，再进入今日概览；其他时间直接显示今日概览。
- 回顾先鼓励、后提醒，并给出评分。

## 方案
- 选用（2026-11-17 用户决定改为混合）：主页界面是本地 HTML 页面 `app/src/main/assets/home/index.html`，在 WebView 里显示；`HomeActivity` 在后台读数据库、算好回顾和评分（纯 Java 类 `home/DailyReview`，有单元测试），以 JSON 交给页面；页面通过 `window.Tempo` 桥（`getData / openSchedule / openAdd / openProfile / startFocus / finishGreeting`）请求跳转。作业要求明确允许 hybrid application。
- 理由：HTML 能在浏览器里按手机尺寸逐像素检查，视觉可以打磨到位；其余页面仍是原生 Java。
- 不选：纯 Java View——设计时看不到真实渲染效果，视觉难以打磨。
- 浏览器预览：直接打开 `index.html` 会用内置演示数据；加 `?review` 查看早晨回顾页。

## 页面
- **问候页**（每天 07:00–09:00 第一次打开时显示一次，用 SharedPreferences 记录日期）：早上好 + 日期；鼓励句 + 完成数 + 专注时长；评分；提醒（低估最多的任务）；“开始今天”按钮。
- **今日概览**：日期；已完成 X / Y、今日专注 N 分钟；下一项（可直接开始专注）；今天的任务列表（按任务汇总，显示开始时间和总分钟数，已完成打勾）；底部“日程 / ＋添加 / 档案”。没有档案时提示先填写。

## 昨日回顾的数据（不依赖 D）
- 计划任务 Y：昨天有日程时段的不同任务；完成 X：其中状态为 COMPLETED 的。
- 专注时长：昨天 completed_at 的反馈 actual_duration 之和。
- 低估：昨天有反馈的任务，累计实际用时（截至昨天结束）− 预估时长，取差值最大的一项。

## 评分算法（我的设计，0–100）
- 完成率（权重 50）：X / Y。
- 专注达成（权重 30）：min(1, 专注分钟 / 昨天计划分钟)。
- 估时准确（权重 20）：对“已完成或已超时”的有反馈任务，取 max(0, 1 − |实际−预估| / 预估) 的平均。
- 缺少某项数据时，该项不计入，按剩余权重重新归一化；三项都没有则不显示评分和回顾。
- 评语：≥90 超棒，≥75 很好，≥60 不错，其余 继续加油。
