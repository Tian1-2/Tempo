# 主页（今日概览）设计 — A

## 目的
主页是打开 App 后的第一个页面。早上先问候并回顾昨天（先鼓励、后提醒、给评分），其余时间直接看今天的安排。19 号 demo 用它讲出 Tempo 的卖点：“你又低估了时间”。

## 已确定（用户决定）
- 主页 = 今日概览，作为启动页。
- 07:00–09:00 打开：先显示问候 + 昨日回顾，再进入今日概览；其他时间直接显示今日概览。
- 回顾先鼓励、后提醒，并给出评分。

## 方案
- 选用：沿用现有页面的写法（Java 代码构建 View，米白/深蓝/薄荷绿），新增 `HomeActivity`；回顾和评分计算放在纯 Java 类 `home/DailyReview`，便于单元测试。
- 不选：XML 布局 + Fragment——和现有页面写法不一致，两天内改造成本高。

## 页面
- **问候页**（每天 07:00–09:00 第一次打开时显示一次，用 SharedPreferences 记录日期）：早上好 + 日期；鼓励句 + 完成数 + 专注时长；评分；提醒（低估最多的任务）；“开始今天”按钮。
- **今日概览**：日期；已完成 X / Y、今日专注 N 分钟；下一项（可直接开始专注）；今天的任务列表（按任务汇总，显示开始时间和总分钟数，已完成打勾）；底部“日程 / ＋添加 / 档案”。没有档案时提示先填写。

## 昨日回顾的数据（不依赖 D）
- 计划任务 Y：昨天有日程时段的不同任务；完成 X：其中状态为 COMPLETED 的。
- 专注时长：昨天 completed_at 的反馈 actual_duration 之和。
- 低估：昨天有反馈的任务，累计实际用时（截至昨天结束）− 预估时长，取差值最大的一项。

## 评分算法（我的设计，0–100）
- 完成率（权重 50）：X / Y。
- 专注达成（权重 30）：min(1, 专注分钟 / 昨天计划分钟)。
- 估时准确（权重 20）：对“已完成或已超时”的有反馈任务，取 max(0, 1 − |实际−预估| / 预估) 的平均。
- 缺少某项数据时，该项不计入，按剩余权重重新归一化；三项都没有则不显示评分和回顾。
- 评语：≥90 超棒，≥75 很好，≥60 不错，其余 继续加油。

## 顺带补上（回顾需要）
- 计时结束弹窗新增“完成任务”：写入 COMPLETED 反馈、任务状态改为 COMPLETED，并把该任务今天的 PLANNED 时段标记为 COMPLETED（这样重新排程不会把它删掉）。
- 日程页左上角小房子改为回到主页；删除 `MainHubPlaceholderActivity`。
